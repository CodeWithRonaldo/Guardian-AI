01 · The Problem

DeFi moves faster than humans can respond

DeFi (Decentralised Finance) is financial software that runs on blockchains. Protocols like lending platforms and decentralised exchanges hold real money — sometimes hundreds of millions of dollars — managed entirely by code.

What is DeFi?

Think of DeFi as a bank with no employees — just software running on a blockchain. Users deposit money, borrow against it, trade assets, and earn yield automatically, without anyone approving anything. Because there are no employees, if something goes wrong there is no human to press the emergency button. That is the problem GuardianAI solves.

The Cetus Exploit — a real example

In October 2025, Cetus — Sui's largest decentralised exchange — was attacked. A bug in the code allowed an attacker to manipulate price calculations and drain liquidity pools. Around $60 million was moved to Ethereum before anyone could stop it.

Monitoring tools detected the attack and sent an alert immediately. But then the human response chain kicked in:

1

Alert fires

Monitoring tool detects the anomaly and sends a notification.

2

A human sees it

Someone has to notice the alert — could be minutes if they are asleep or busy.

3

A human understands it

They have to read it, understand what is happening, and decide what to do.

4

A human acts

They coordinate with the team, sign a transaction, pause the protocol.

That chain takes minutes at best. The attacker operated in seconds. By the time humans coordinated, the money was gone.

The missing piece is not better detection. It is faster response — autonomous on-chain response that does not wait for a human. That is what GuardianAI is.

02 · The Solution

What GuardianAI actually does

GuardianAI sits alongside any DeFi protocol and does three things continuously, every 3–4 seconds, around the clock:

W

Watches

Reads live price data from three sources: Pyth (a blockchain price oracle), Deepbook (Sui's native on-chain DEX), and the protocol itself on the Sui blockchain. All happening in the background, continuously.

T

Thinks

A risk engine scores the current situation from 0 to 100. It combines nine signals — including a real AI anomaly detector (statistical z-score analysis), DEX-oracle price divergence, pool drain speed, and oracle staleness — into one risk score that updates every few seconds.

A

Acts

When the score crosses a threshold, the system does not send an alert — it executes a protective action directly on the blockchain. In under 4 seconds. No human required.

Every action is logged permanently on-chain. The protocol team can see what happened and why, and can override it with one click. The human sets the rules; the agent enforces them at machine speed.

04 · Smart Contracts

The Move smart contracts

What is a smart contract?

A smart contract is a program that lives on the blockchain. It runs automatically when triggered and nobody can change it once deployed. Think of it as a vending machine — put in the right input, get the right output, with no human deciding anything. Move is the programming language Sui uses to write smart contracts.

What is Sui?

Sui is a blockchain — a decentralised database that records transactions. It is faster than most blockchains (transactions confirm in under a second) and uses Move, which has strong safety guarantees built in. GuardianAI is built on Sui specifically because Move's type system makes the permission model safe in a way that is not possible on other blockchains.

The GuardianAI contracts are deployed on Sui testnet at package: 0x50b1a7151841d91039798ceabf37fb2bac34810d789e410e8a27f06e44ac9b2d. There are three modules:

🔑
guardian_ai::cap — The Permission System
contracts/guardian_ai/sources/cap.move

This module defines two capability objects that control who can do what. A capability object in Sui is like a physical key — hold the key, have permission. Don't hold it, and the blockchain rejects your transaction.

ObjectWho holds itWhat it allows
GuardianCap The agent wallet (backend server) Call circuit breaker functions — pause protocol, tighten LTV
AdminCap Protocol team wallet Enable/disable the guardian, unpause, reset LTV. Full override.
GuardianConfig Shared object — anyone can read Stores whether the guardian is currently enabled. Circuit breaker functions check this before acting.

Why this matters: Move's type system enforces these permissions at the Virtual Machine level. You cannot call a function that requires &GuardianCap unless you literally own a GuardianCap object in your wallet. Not a password. Not an API key. A cryptographic object the blockchain itself verifies. This is the security foundation of the entire system.

📋
guardian_ai::action_log — The Audit Trail
contracts/guardian_ai/sources/action_log.move

Defines a shared object called ActionLog that records every action the guardian takes. It is append-only — entries can be added but never deleted. Anyone — the protocol team, their users, auditors — can read the full history at any time.

Each log entry contains: timestamp, risk score at the time, the action taken (as a code number), and a plain English reason. Full signal details are stored separately on Walrus to keep on-chain gas costs low.

Object ID on testnet: 0xb48afb54dc8ea14e2674e2ebd5b0fb67504b10547cb7e4516da8f1e39231f827

🏦
guardian_ai::test_protocol — The Reference Lending Protocol
contracts/guardian_ai/sources/test_protocol.move

This is a reference DeFi lending protocol used for the hackathon demo. It represents the code a real protocol team would add to their own contract when integrating GuardianAI. In production, this code would live in the protocol's own package.

It has a realistic on-chain state — 10,000 SUI pool balance, 80% LTV ratio — and four functions:

  • pause_protocol — requires GuardianCap. Halts all protocol activity.
  • tighten_ltv — requires GuardianCap. Reduces the LTV ratio by a configured amount.
  • unpause_protocol — requires AdminCap. Resumes activity (human override).
  • simulate_pool_drain — requires AdminCap. Demo only — drains the pool to trigger risk signals.

05 · Backend Risk Engine

The Node.js risk engine

The backend is a Node.js service running on Render (a cloud hosting platform). It never stops running, never sleeps, and makes all the risk decisions. It is split into files with single clear jobs:

What is an oracle?

A blockchain on its own does not know what the price of SUI is. It only knows what transactions have happened. An oracle is a service that brings real-world data (like prices) onto the blockchain. Pyth is our oracle — it publishes SUI/USD prices every few seconds on Sui. Our backend reads those prices off-chain via Pyth's Hermes API.

What is Deepbook?

Deepbook is Sui's native on-chain order book exchange (like a stock exchange, but on the blockchain). It lets the backend read the actual trading price of SUI from the live order book and compare it to Pyth's oracle price. If those two prices diverge significantly, that is a strong signal that something is wrong — an attacker may be manipulating one of them.

What is TWAP?

TWAP stands for Time-Weighted Average Price. Instead of only looking at the current price, the system keeps the last 20 price readings (about 60 seconds of data) and calculates their average. This gives a stable "normal" baseline. If the current price suddenly jumps far above or below that average, it is a signal that something unusual is happening.

What is RPC?

RPC stands for Remote Procedure Call. On Sui, it is simply the way software talks to the blockchain. Instead of a human using a wallet app, the backend sends a request to a Sui RPC server (run by the Sui Foundation) and asks: "what is the current state of this object?" The server reads the blockchain and sends back the answer. Free, instant, no transaction needed.

FileWhat it does
pyth.js Fetches SUI/USD price from Pyth's Hermes API every 3 seconds. Calculates a rolling TWAP (time-weighted average) over the last 20 readings. Measures how much the current price deviates from the TWAP. Also runs an AI z-score analysis to detect statistical anomalies, and checks if the oracle feed is stale (not updated in over 30 seconds).
deepbook.js Reads the live mid-price from the SUI/DBUSDC pool on Deepbook every 4 seconds. Uses the Sui TypeScript SDK to call the Deepbook smart contract directly on-chain (a read-only "inspect" call — no transaction fee). Returns the DEX price for comparison with Pyth.
chain.js Reads the Protocol shared object from Sui every 4 seconds via RPC. Gets pool balance, LTV ratio, and paused flag. Computes how much the pool balance has dropped since the last reading.
scorer.js The risk scoring engine. Combines nine signals (including AI anomaly and DEX-oracle divergence) into a single score from 0–100. Each signal has a weight. The final score is the weighted sum, capped at 100.
executor.js When told to act, builds and signs a Programmable Transaction Block (PTB) using the agent wallet's private key, then submits it to the Sui RPC. Handles the pause and tighten_ltv actions. The module and function names it calls are configured via environment variables — no code change needed to integrate with a real protocol.
walrus.js After every on-chain action, stores a full JSON audit record to Walrus — the decentralised storage network. Contains raw signal values, z-score, Deepbook price, Pyth price, pool balance, and the transaction digest.
config.js Loads all configuration from environment variables. Covers required IDs (package, protocol object, wallets) and optional integration settings (protocol module name, function names, field names). This is how you connect GuardianAI to any protocol without touching code.
index.js The main entry point. Runs three polling loops (Pyth, Deepbook, chain state), calls the scorer, decides what action to take, and runs a small Express HTTP server for the dashboard to query.

The AI anomaly detector (z-score)

This is real statistical AI, not just a rule. Here is how it works in plain language:

1

Build a rolling history

Every time Pyth returns a price, we keep the last 20 readings in memory (about 60 seconds of data).

2

Calculate the average and spread

We compute the mean (average) price and the standard deviation (how spread out the prices have been). This tells us what "normal" looks like for this window.

3

Measure how abnormal the current price is

The z-score is: (current price − average) ÷ standard deviation. A z-score of 0 means perfectly normal. A z-score of 2.5 means the price is 2.5 standard deviations from normal — statistically unusual. A score above 2.5 is flagged as an anomaly.

4

Add to risk score

If an anomaly is detected (z-score > 2.5), +20 is added to the overall risk score.

The nine risk signals

The scorer combines nine signals. A single minor event stays low. The pattern of a real attack — price moving, DEX diverging, pool draining — spikes the score fast.

SignalScore AddedWhat it means
Price deviates >10% from TWAP +30 Price is moving very fast — possible oracle manipulation
Price deviates 3–10% from TWAP +15 Price is moving unusually fast — worth watching
AI anomaly detected (z-score > 2.5) +20 Statistically abnormal price movement detected by the AI engine
DEX-oracle divergence >3% +25 Deepbook's DEX price and Pyth's oracle price are significantly different — possible manipulation of one feed
Oracle stale >30 seconds +20 Price feed stopped updating — possible oracle attack
Pool balance dropped >20% this interval +35 Large, sudden pool drain — classic exploit signature
Pool balance dropped 5–20% +15 Smaller drain — could be normal activity or early exploit
Pool balance <1% of baseline +90 Pool is almost completely drained — emergency, act immediately
Protocol already paused on-chain +10 Paused flag already set — informational signal
What is LTV ratio?

LTV stands for Loan-to-Value ratio. In a DeFi lending protocol, if you deposit 100 SUI as collateral, the LTV ratio determines how much you can borrow against it. An LTV of 80% means you can borrow up to 80 SUI worth of assets. When GuardianAI "tightens" the LTV, it lowers that ratio — say from 80% to 70% — so new borrowers can borrow less. This protects the protocol from risky under-collateralised positions during volatile or suspicious periods.

What happens at each score level

ScoreActionOn-chain?

What is a PTB?

PTB stands for Programmable Transaction Block. On Sui you can bundle multiple operations into one atomic block. The executor builds one of these blocks, signs it with the agent wallet's private key, and sends it to Sui. If it is accepted, all operations execute together. If anything fails, none of them execute.

06 · Frontend Dashboard

The React dashboard

The frontend is a React web application built with Vite. It uses the @mysten/dapp-kit library to connect Sui wallets and read on-chain data. It polls the backend every 4 seconds for a live feed. It has four pages.

◈
Dashboard
The main live monitoring screen

Shows: a semicircular risk gauge (green → orange → red), the current SUI/USD price from Pyth, the Deepbook DEX price, the AI z-score (turns red when anomaly is detected), and on-chain protocol state (LTV ratio, pool balance, paused/active status).

Below the stats is a live score chart — it records the risk score every 4 seconds and plots the last ~50 readings as a continuous line chart. This makes it easy to see the score climbing during an attack in real time.

≡
Action Log
The permanent on-chain audit trail

Shows every action the guardian has ever taken, pulled directly from the ActionLog shared object on Sui. Each entry shows the timestamp, risk score at the time, the action taken (colour-coded), and the plain English reason.

This is not a backend database — it reads the blockchain directly. The data is permanent and cannot be deleted or edited by anyone, including GuardianAI.

⚙
Configuration
Guardian settings and on-chain permissions

Where the protocol team manages the guardian:

  • Guardian toggle — Enable or disable the guardian with one click. Requires the AdminCap wallet to be connected. Signs and submits an on-chain transaction.
  • Risk threshold sliders — Set the score at which each action fires. Saved to the backend via POST /config and to localStorage.
  • LTV tighten amount — How many basis points (1 basis point = 0.01%) to reduce LTV when the tighten action fires.
  • Webhook URL — Paste a Discord, Slack, or any HTTP webhook. The backend posts an alert here when the risk score crosses the Notify threshold.
▶
Simulation
The demo tool — no real transactions

Replays a 30-second Cetus-style exploit scenario entirely in the browser. No real transactions, no CLI required. The gauge climbs in real time, signals turn red, and the system shows which action would fire and when.

The scenario is based on the actual Cetus attack pattern: gradual price deviation, then oracle staleness, then rapid pool drain. The score climbs from 0 to 80+ over 30 seconds, triggering Notify then Tighten LTV actions with visible timestamps.

07 · Walrus Integration

What Walrus is and why we use it

What is Walrus?

Walrus is a decentralised storage network built by the Sui team. Instead of storing files on Amazon S3 (centralised, can be shut down), Walrus stores data across a distributed network. Once stored, the data gets a unique ID (called a blob ID) and can be retrieved by anyone. It is one of the hackathon tracks, which is why we integrate it.

We use Walrus for two things:

1. Extended audit records. The on-chain ActionLog keeps entries small to minimise gas costs — it stores the action code and a short reason string. After every autonomous action, the backend writes a full JSON blob to Walrus containing all raw signal values, z-score, Deepbook price, Pyth price, pool balance, the transaction digest, and timestamp. The Walrus blob ID links the compact on-chain entry to the full context.

2. Verifiable audit trail. Protocol teams and their users can independently verify what the guardian saw and why it acted. Nobody can modify or delete the blob after it is stored.

08 · Security Model

Why there are two wallets

What is a private key?

A private key is a secret password that proves you own a wallet. Every wallet on Sui has a public address (like a bank account number — safe to share) and a private key (like the PIN — never share it). When the backend "signs a transaction," it uses the private key to prove to the Sui blockchain that the instruction genuinely came from the agent wallet. Anyone who has the private key controls that wallet completely, which is why it is stored securely on the server and never put in the code.

The system uses two separate wallets deliberately. Each represents a different entity with a different level of trust.

WalletAddressHoldsCan do
Admin wallet
(Protocol team)		 0xdab28d...f390 AdminCap Enable/disable guardian, unpause protocol, reset LTV, full override
Agent wallet
(Backend server)		 0xc56efa...1339 GuardianCap Pause protocol, tighten LTV. Nothing else.

The agent wallet's private key lives in the backend's environment variables on Render. It signs transactions automatically. But it can only sign transactions that call functions accepting &GuardianCap — only the circuit breaker functions explicitly written by the protocol team.

If the backend were ever compromised, the attacker would have the agent key. They could pause the protocol or tighten LTV — both recoverable actions. They could not withdraw funds, change ownership, or do anything outside the GuardianCap's scope. The AdminCap wallet is completely separate and the backend never touches it.

Think of it like a security guard at a building. The guard has a key to lock the front door in an emergency — but not the master key to every room and the safe. Two keys, two levels of trust.

09 · Real Protocol Integration

How a real protocol would plug in

What are environment variables?

Environment variables are settings stored outside the code — on the server itself, not in the project files. Think of them like a configuration panel the server reads at startup. This means you can change how the backend behaves (which protocol to guard, which functions to call, what the field names are) without changing a single line of code and without redeploying. On Render (our cloud host), you set them in a simple settings screen. The backend reads them automatically every time it starts.

GuardianAI is designed so a real DeFi protocol can integrate it without touching the GuardianAI source code. All the protocol-specific names are configurable via environment variables.

1

Protocol team adds the two functions to their contract

They add a pause_protocol and tighten_ltv function to their existing Move contract. These functions accept &GuardianCap as a parameter — that is all that is needed to give GuardianAI permission to call them.

2

Deploy and collect object IDs

Deploy the updated contract and collect the protocol object ID, package ID, and field names for pool balance, LTV ratio, and paused flag.

3

Update the backend environment variables — no code changes

Set the env vars in Render to point at their package and protocol object. Set the module name, function names, and field names to match their contract. The backend picks everything up on the next restart.

4

Connect the dashboard

Update the frontend env to point at their protocol object ID. The dashboard reads all state from the chain, so it automatically shows their pool balance and LTV.
