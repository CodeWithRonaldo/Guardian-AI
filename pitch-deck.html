Scores are additive, capped at 100. Score ≥ 85 → autonomous protocol pause. The z-score adapts to market volatility — a 3% move can be normal or anomalous depending on recent price history. When a threshold is crossed, Claude Haiku generates a one-sentence explanation that is written as the reason field in the on-chain ActionLog — making every entry in the permanent audit trail human-readable without any off-chain lookup.
Why Sui
Sui Is Load-Bearing — Not Bolted On
🔐 Move Capability Objects
GuardianCap is a Move object. Every circuit breaker requires it as a parameter. The Move VM enforces the agent's scope — not application code. The agent can't move funds, upgrade contracts, or unpause. Sui makes the AI safer — its permissions are type-enforced at the VM level, not in application logic that could be bypassed.
⚙️ Programmable Transaction Blocks
Every guardian action is a PTB — composable, atomic, signed by the agent keypair. The decision-to-execution chain is a single transaction. Sui makes the AI more composable — multiple protocol operations can be batched into one atomic PTB, reducing gas and preventing partial-state exploits.
📋 On-Chain ActionLog + AI Reasons
A shared, append-only Sui object stores every action with a Claude-generated plain-English reason. Sui makes the AI auditable — the audit trail is trustless and permanent, not stored in a centralized database the operator controls.
📊 Deepbook + Walrus
Deepbook provides a native on-chain DEX price — a Sui-specific signal unavailable on any other chain. Walrus stores full diagnostic blobs after every action. Sui makes the AI better — the DEX-Oracle divergence signal only exists because Deepbook is native to Sui.

Security Model
Narrow Permissions. Instant Kill Switch. Full Audit Trail.
What the agent CAN do
  • ✓Pause the protocol (sets paused flag)
  • ✓Tighten the LTV ratio (reduce only, never raise)
  • ✓Append to ActionLog with timestamp and reason
What the agent CANNOT do
  • ✕Move or withdraw any funds
  • ✕Upgrade contracts
  • ✕Transfer ownership of any object
  • ✕Unpause the protocol
  • ✕Call any function not accepting GuardianCap
Kill switch: The protocol team holds AdminCap. Calling cap::disable sets GuardianConfig.enabled = false. Every circuit breaker calls assert_active at the top — it aborts instantly. One transaction. No code change. Permanent record in the audit trail. One-click in the dashboard.
Integration
Any Sui Lending Protocol. No Architecture Changes.
1
Add two functions to your Move contract
pause_protocol and tighten_ltv — both accept GuardianCap as a parameter. Your existing contract logic stays unchanged. Integration is additive.
2
Run one-time guardian initialisation
One CLI command creates GuardianCap (agent wallet), AdminCap (protocol team), and GuardianConfig (shared). Another creates the ActionLog shared object.
3
Configure the backend via env vars
PROTOCOL_MODULE, PAUSE_FUNCTION, POOL_BALANCE_FIELD — match these to your contract's module and field names. No source code changes needed.
4
Deploy and tune thresholds live
The Configuration panel lets you adjust Notify, Tighten LTV, and Pause thresholds in real time — no backend restart. Add a Telegram or Discord webhook for instant alerts.
Existing protocol logic is untouched. Integration is purely additive.
